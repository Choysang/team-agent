# GitHub Copilot 适配（VS Code与Copilot CLI）

识别依据：VS Code本地Agent的派发工具为 `runSubagent`；Copilot CLI为原生 `task` 工具；系统提示为GitHub Copilot。核对日期：2026-10-27，依据官方文档，尚未在本机实测。

## 宿主事实

| 项目 | 行为 |
|---|---|
| 自定义代理文件 | `*.agent.md`。Copilot CLI用户级 `~/.copilot/agents/`（与项目同名时用户级优先）；仓库级 `.github/agents/`。VS Code也读取 `.claude/agents/`（Claude格式） |
| `model` | 字符串或数组；数组按顺序使用第一个可用模型，正好对应本技能的有序备选链。未设置时继承默认模型 |
| `reasoning-effort` | low/medium/high/xhigh/max，取决于所选模型（Copilot harness） |
| 其他字段 | `tools`、`agents`（可调度的子代理）、`user-invocable`、`disable-model-invocation`（取代旧的 `infer`） |
| VS Code模型优先级 | runSubagent传入的model > 代理 `model` > `chat.subagents.defaultToAuto` 开启时用Auto > 主会话模型 |
| 成本层限制 | VS Code中子代理模型必须不高于主会话模型的成本层，否则子代理不运行。选择卡里给出此提醒 |

## 主方案

`team-*.agent.md` 的 `model` 有序列表（即备选链，宿主自己取第一个可用的）与 `reasoning-effort`。VS Code的runSubagent可在单次调用传model，升级阶梯按此显式传，受主会话成本层限制。

## 执行步骤

状态目录：`~/.team-agent/copilot/`。

1. 选择卡：模型选项用你当前可用的Copilot模型名；强度只列该模型支持的值。备选直接写成 `model` 数组，不需要failover切换。
2. 写代理文件 `team-<职能>.agent.md`：Copilot CLI写到 `~/.copilot/agents/`；VS Code的用户级位置以当前版本“Create agent”向导为准；需要团队共享时写到仓库 `.github/agents/`（需用户同意写入项目）。
   ```markdown
   ---
   name: team-reviewer
   description: Independent code reviewer for concrete defects and risks.
   model: ['<首选模型>', '<备选1>']
   reasoning-effort: high
   tools: ['read', 'search']
   user-invocable: false
   ---

   <职责说明>

   <!-- generated by team-agent; edit the profile, not this file -->
   ```
   Reviewer、Researcher、Explorer只给读和搜索类工具；字段值以你当前环境的工具名为准。
3. 路由：在仓库 `.github/copilot-instructions.md` 或用户级说明中写入 `<!-- team-agent:copilot routing:start/end -->` 受管块，说明各职能使用哪个代理。
4. `chat.subagents.defaultToAuto` 是VS Code设置；用户希望未配置的职能交给Auto时才建议开启，由用户在设置界面中修改。
