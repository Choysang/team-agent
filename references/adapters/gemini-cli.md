## 宿主事实

| 项目 | 行为 |
|---|---|
| 自定义子代理 | 用户级 `~/.gemini/agents/*.md`，项目级 `.gemini/agents/*.md`；frontmatter的 `name` 同时是主代理看到的工具名 |
| frontmatter | `name`、`description` 必填；`model`（模型ID，默认 `inherit`）；`temperature`(0–2)、`max_turns`(默认30)、`timeout_mins`(默认10)；`tools`（省略则继承全部）；`kind`、`mcpServers` |
| 内置子代理改模型 | `~/.gemini/settings.json`：`agents.overrides.<名称>.modelConfig.model`；`runConfig` 可设 `maxTurns`/`maxTimeMinutes` |
| 思考强度 | 子代理文档未提供；`modelConfigs.overrides[].modelConfig.generateContentConfig` 可按 `overrideScope` 指定子代理名，但未写明思考字段。默认显示“不支持”；只有你在当前版本的设置schema中确认存在思考字段时，才提供强度题 |
| 单次调用参数 | 子代理即工具，没有模型参数 |
| 关闭子代理 | `experimental.enableAgents: false` |

## 主方案

`settings.json` 的 `agents.overrides.<内置>.modelConfig.model` + `~/.gemini/agents/team-*.md` 的 `model`。子代理即工具，没有单次调用参数；升级阶梯改派配置更强模型的职能代理，再由主代理亲自完成。

## 职能到子代理

| 职能 | 目标 | 写入位置 |
|---|---|---|
| Explorer | 内置 `codebase_investigator` | settings.json overrides |
| Executor、GeneralWorker | 内置 `generalist` | settings.json overrides（两者共用时取Executor的配置，并在汇报中说明） |
| Reviewer、Researcher、Designer、ExpertAdvisor | 自定义 `team-<职能>` | `~/.gemini/agents/` |

## 执行步骤

状态目录：`~/.team-agent/gemini-cli/`。

1. 选择卡：模型选项来自你当前可用的Gemini模型ID（与主会话同一服务商）；强度题默认跳过。
2. 内置子代理：读入 `~/.gemini/settings.json`，只设置 `agents.overrides.codebase_investigator.modelConfig.model` 和 `agents.overrides.generalist.modelConfig.model`，保留其余键；inherit的职能删除自己写过的这一项，不动用户原有值。文件无法解析时不改。
3. 自定义子代理 `~/.gemini/agents/team-<职能>.md`：frontmatter写 `name`、`description`、`model`（inherit时省略）；Reviewer与Researcher用 `tools` 限定为只读工具（从你的工具定义中逐字抄写名称）；正文写职责，并附生成标记 `<!-- generated by team-agent; edit the profile, not this file -->`。
4. 路由说明：项目或用户的 `GEMINI.md` 中写入 `<!-- team-agent:gemini-cli routing:start/end -->` 受管块。`~/.gemini/GEMINI.md` 也可能被Antigravity读取，块内注明“仅适用于Gemini CLI”。
5. 设置在启动时加载，告知用户下次启动生效。

## 验证

- 静态：重读settings.json与子代理文件。
- 运行：新会话派发后，Gemini CLI的 `/stats` 会按模型列出用量，请用户查看；本地没有可供你读取的子代理模型记录时，结论保持“已写入，运行未验证”。
