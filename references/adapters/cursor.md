## 宿主事实

| 项目 | 行为 |
|---|---|
| 子代理文件 | 用户级 `~/.cursor/agents/`；也读取 `~/.claude/agents/`、`~/.codex/agents/`。项目级优先于用户级；同级中 `.cursor/` 优先于 `.claude/`、`.codex/` |
| frontmatter | `name`（默认文件名）、`description`、`model`（默认 `inherit`）、`readonly`、`is_background` |
| 模型与强度 | `model` 为 `inherit` 或Cursor模型ID；附加选项写在方括号里，如 `claude-opus-5[effort=high]`、`[context=300k]`、`[fast=false]`。可用选项取决于模型 |
| 内置子代理 | Explore（默认用更快的模型）、Browser；未提供改模型的方法 |
| 单次调用 | 主代理启动子代理时可以指定模型 |
| 已知限制 | 旧的按请求计费且未开Max Mode的方案，子代理一律用Composer；论坛有“子代理模型选择未被遵守”的报告。务必实测 |

## 主方案

`~/.cursor/agents/team-*.md` 的 `model: <Cursor模型ID>[effort=…]`，并遮蔽其他宿主的同名文件。主代理启动子代理时可以指定模型，升级阶梯按此显式传；仍需实测确认被遵守。

## 执行步骤

状态目录：`~/.team-agent/cursor/`。

1. 选择卡：模型选项用你当前可选的Cursor模型ID；强度作为该模型的方括号选项提供，只列该模型支持的值，不确定时只给模型不给强度。
2. 写 `~/.cursor/agents/team-<职能>.md`（每个配置了非inherit的职能一份）：
   ```markdown
   ---
   name: team-reviewer
   description: Independent code reviewer. Use proactively after code changes to find concrete defects and risks.
   model: <Cursor模型ID>[effort=<强度>]
   readonly: true
   ---

   <职责说明>

   <!-- generated by team-agent; edit the profile, not this file -->
   ```
   Explorer、Reviewer、Researcher、ExpertAdvisor设 `readonly: true`。
3. 遮蔽其他宿主的同名文件：`~/.claude/agents/` 或 `~/.codex/agents/` 中已有team-*文件时（Claude Code或Codex适配生成的），Cursor会读到 `opus`、`gpt-…` 这类不属于Cursor的值。给每个同名文件在 `~/.cursor/agents/` 放一份Cursor版本；即使该职能在Cursor中是inherit，也写一份 `model: inherit` 的遮蔽文件。
4. 路由：Cursor的用户规则只能在设置界面中编辑，你无法写入文件。依靠子代理 `description`（加“Use proactively for …”）引导委派；项目内可写 `.cursor/rules/team-agent.mdc` 受管规则（需用户同意写入项目）。
5. 内置Explore无法改模型；需要指定Explorer模型时，路由规则让主代理改用 `team-explorer`。

## 验证

Cursor没有可供你读取的本地子代理模型记录。新会话派发后，请用户在子代理面板查看实际模型；结论保持“已写入，运行未验证”，并提醒上面的计费方案限制。
