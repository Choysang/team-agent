# 宿主自适配：用当前Agent自己核对并沉淀适配卡

[返回主流程](../SKILL.md) · [能力与宿主分流](harness-matrix.md)

当前Agent最了解自己所在的宿主。每次使用本技能时，先确认本宿主的适配卡是否可信；不可信时，由当前Agent用宿主自己的渠道核对，再把结果写回适配卡。下次任何Agent在同一宿主上使用，直接读到更新后的卡。

## 1. 判断要不要自检

有Python 3.10+时运行：

```text
python scripts/adapter_status.py status --host <宿主ID> --host-version <你查到的宿主版本>
```

宿主ID是适配卡文件名（如claude-code、codex、antigravity）。宿主版本从你自己的环境取得（命令行的版本参数、应用的关于信息、系统提示）；查不到就省略该参数。

| 结果 | 动作 |
|---|---|
| fresh | 直接使用适配卡 |
| stale（超过90天、宿主版本变化、缺元数据） | 做第2步自检 |
| missing（还没有这张卡） | 做第2步自检，并按第4步模板新建卡片 |

另外两种情况也要自检：现场发现与卡片矛盾（工具参数不存在、设置键被拒、运行验证不一致），或者用户要求。没有Python时，直接读卡片第二行的 `<!-- adapter: ... -->` 元数据自行判断。

## 2. 自检：按可信度从高到低取证

1. **你自己的工具定义**：子代理派发工具的名称、参数、参数枚举（模型、强度）。这是现场事实，优先于任何文档。
2. **宿主自带的说明**：内置帮助技能或指南子代理、`--help`、本机安装目录里的内置文档。
3. **本机配置**（只读）：角色文件目录、设置文件、环境变量，确认路径与字段真实存在。
4. **官方在线文档**：用搜索和抓取工具核对，记下链接。
5. **一次最小实测**：按卡片的主方案派一个最小子代理（“只回复pong，不用工具”），从宿主可读的运行记录核对实际模型与强度。

要回答的问题：

- 角色文件放在哪里、字段名与取值；内置角色有哪些、能不能改模型。
- 单次调用能否传模型与强度（决定升级阶梯能否完整执行）。
- 有没有按名称改模型的设置键，或会压过一切的环境变量。
- 运行证据在哪里可读。
- 按 [主流程](../SKILL.md) 第4步的原则，哪一种是该宿主唯一的主方案，前提不满足时的唯一降级方案是什么。

## 3. 对比与沉淀

1. 列出差异：项目 | 卡片原值 | 现场结果 | 依据（工具定义 / 内置说明 / 本机文件 / 文档链接 / 实测记录）。没有差异时只更新元数据。
2. 交互会话中，把差异摘要给用户看，用户同意后再写。无人值守时不改技能文件，把差异写到 `~/.team-agent/<宿主ID>/self-check.md` 并在汇报中说明。
3. 只改当前宿主自己的卡片：宿主事实、主方案、执行步骤、验证。不改其他宿主的卡片，不写入用户的个人选择或个人路径（那些在 `~/.team-agent/<宿主ID>/`）。
4. 同步更新 [能力与宿主分流](harness-matrix.md) 中本宿主那一行；新宿主再加一行识别依据。README的宿主覆盖表与维护记录各补一行。
5. 盖章（证据等级：做了第5项实测为tested，读了本机文件为local，仅文档为docs）：

```text
python scripts/adapter_status.py stamp --host <宿主ID> --verified <今天日期> --evidence <tested|local|docs> --host-version <版本>
```

6. 改了脚本时运行相关测试；有oil-skill-creator时运行其校验器。然后重新读取更新后的卡片，继续本次任务。

技能可能装在多个位置（例如多个宿主的技能目录）。写入你实际加载的那一份；若它是指向同一源目录的链接，各处自动一致；否则在汇报中列出其他副本，提醒用户同步或改为链接。

## 4. 新卡片模板

```markdown

```
